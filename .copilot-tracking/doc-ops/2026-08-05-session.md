## Requirements

Rewrite `docs/implementation-guide.md` to provide customers with a prescriptive,
intuitive, structured, comprehensive, and clear process for establishing the
required range of budget profiles across an enterprise.

## Discovered Issues

### Pattern Compliance

Discovery reviewed four in-scope documentation files and found 18 grouped
issues: 3 errors, 10 warnings, and 5 suggestions. The target guide needs
frontmatter, prerequisites, named owners, procedures, outputs, validation
criteria, examples, exception handling, and measurable review thresholds.
Unrelated README table formatting and naming-standard cleanup remain outside
this request.

### Accuracy Discrepancies

Nine confirmed discrepancies affect the guide:

* Included credits are estimated from license inventory and configured rates;
  only usage is retrieved from GitHub
* The application reads GitHub governance data but does not create budgets,
  teams, cost centers, or policy settings
* Copilot policy settings are not retrieved or applied by the assessment
* Classes 7 through 10 are organization policy profiles, not organization
  budget classes
* Simulator license counts remain manually confirmed planning assumptions
* Built-in profile identifiers do not follow the published naming patterns
* Recurring monitoring, feedback, training, and adjustment are external
  operating-model activities rather than application automation
* Live assessment uses promotional Business and Enterprise rates through
  August 31, 2026, while simulator and PDF calculations use standard rates
* Current-month assessment and several dashboard metrics include synthesized
  or heuristic data that must not be presented as raw telemetry

### Missing Documentation

Thirteen implementation-backed documentation gaps were identified. The guide
needs the ten-class profile catalog, three-tier hierarchy, assignment criteria,
profile parameters, simulator assumptions, input constraints, data provenance,
fallback behavior, recommendation thresholds, reconciliation controls, report
review requirements, and a recurring governance cadence.

The most important profile details are:

* Classes 1 and 2 govern the included pool and enterprise spending limit
* Class 3 is the 5,000-credit Universal ULB
* Classes 4 through 6 are 6,000, 7,000, and 8,000-credit cost-center overrides
* Classes 7 through 10 are organization policy profiles
* Applicable budget classes use 75% and 90% alerts and hard-stop behavior
* The implemented hierarchy is enterprise spending limit, Universal ULB, then
  cost-center ULB overrides

## Work Plan

1. Correct capability and source-of-truth claims with a matrix that separates
  GitHub data, application calculations, heuristics, and manual customer work.
2. Define outcomes, prerequisites, accountable roles, approvals, and required
  inputs before customers begin configuration.
3. Document the three-tier hierarchy and exact parameters for budget profile
  Classes 1 through 6.
4. Document Classes 7 through 10 as organization policy profiles and provide
  evidence-based, advisory assignment criteria for all classes.
5. Establish naming, profile mapping, ownership, and profile-register records.
6. Replace the loose task list with assessment, design, approval, pilot, and
  rollout phases that each have inputs, outputs, gates, and validation.
7. Add input validation, partial-data handling, rate-basis reconciliation, and
  controls for resolving variances.
8. Define measurable monitoring, escalation, exceptions, review cadence, and
  change control.
9. Add required frontmatter, evidence and report checklists, a glossary, and a
  clear reference structure.

Acceptance requires exact alignment with implemented profile values, explicit
manual-action boundaries, auditable decision ownership, valid Markdown, and no
claims that calculated or synthesized values are raw GitHub telemetry.
